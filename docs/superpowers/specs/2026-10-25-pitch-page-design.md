# 路演网页 `/pitch` 设计

> 2026-10-25 · 状态：待用户确认 · 关联待办：`docs/todo/2026-10-25-portrait-evolution-and-reroute.md`

## 1. 意图

路演在大屏上进行，**这个网页取代 PPT**，整场路演都在它上面讲完；中段切到嵌入的真实 App 现场演示。

**核心立意（全场只讲这一件事）**：**目标是静态的，人是动态的。** 少做、照做、超额完成，UworthBetter 都会让「未来的你」跟着真实行动不断拟合，90 天后你能清楚看到自己真正发生了哪些转变。画像只拟合，不评判。

叙事要求：研究依据不是一摞论据，而是一条**推理链**，每一条研究都回答一个问题，并引出产品的一块设计，最后汇合成项目简介。功能出场之前，观众已经知道它为什么存在。

## 2. 目标 / 非目标 / 反目标

**目标**
- 投到大屏上，后排也看得清；演讲者用键盘或翻页笔推进。
- 研究推理链让人信服；「画像演化」一屏要做到全场最震撼。
- 现场演示用的是真实 App（真实接口、真实生成），证明「这东西真能跑」。
- 部署到服务器后，在任何一台能上网的电脑上打开网址就能完整讲完。

**非目标**
- 不做移动端适配；不做 SEO；不对外公开宣传。
- 不实现画像演化 / 目标改道的产品逻辑（见关联待办，其他人并行开发）。

**反目标（技术上能跑，也算失败）**
- 做成「网页版 PPT」：满屏文字、要点列表。每屏最多一个主张。
- 开场就讲失败、把用户框成「坚持不下来的人」，和核心立意冲突。
- 画像演化被理解成「打分 / 惩罚」，比如偷懒的分支被画成变丑、变暗。
- 现场演示卡住时没有退路。

## 3. 约束

- Next.js 16 App Router、React 19、TypeScript strict、Tailwind v4、framer-motion 14（已安装），不新增依赖。
- 目录归属：`app/pitch/**`、`components/pitch/**` 属于 C 轨道；需要改动 `components/layout/MobileShell.tsx` / `AppChrome.tsx`（C 轨道）。开工前在群里打招呼。
- `lib/contracts/`、`schema.ts` 只读。
- 根布局 `app/layout.tsx` 会把所有页面包进 `MobileShell`（手机外框）+ `AppChrome`（`TabBar`、`DemoPanel`）+ `PaperBackground`。`/pitch` 必须绕开这些。
- App 在视口宽度 ≤760px 时会自动去掉自己的手机外框（`app/globals.css` 的 `@media (max-width: 760px)`）。
- 中文 UI 文案；注释用简体中文。`pnpm check` 必须通过。
- 现场网络不可控：除了 iframe 演示那一屏，其余内容都不能依赖接口或外部资源（字体已在本地，通过 `@fontsource`）。

## 4. 方案选择

| 方案 | 取舍 |
|---|---|
| **① 在 Next 里加 `/pitch` 路由，用 React + framer-motion（已选）** | 和 App 一起部署，天然同源，iframe 演示最稳；复用字体、配色、`public/demo/` 素材；framer-motion 撑得住镜头动画。代价是要碰 C 轨道的布局文件 |
| ② 在 `public/pitch/` 放独立静态 HTML | 完全隔离，但读不到 seed 数据，样式要重写 |
| ③ 用 reveal.js 之类的幻灯片框架 | 翻页功能现成，但命运树的连续镜头会被翻页模型卡住，还要新增依赖 |

用户选择了 ①。

## 5. 已确定的内容（用户决定）

- 网页取代 PPT。
- 叙事骨架：开场（真实经历）→ 研究推理链 → 汇合成项目简介 → 产品 → 现场演示 → **画像演化（高潮）** → 差异化 → 技术 / 商业 / Roadmap → 收尾。
- 开场不以「92% 会失败」作为主钩子；三种人（忘了 / 懒了 / 超额完成）都是真实的人生。
- 画像演化一屏：**先用 A「命运树」讲清逻辑，再把镜头拉远，变成 C「平行宇宙墙」**。
- 素材：命运树中露脸的画像提前生成 8–16 张并人工挑选；满墙的几十张用这些图做变体（滤镜 / 裁切 / 镜像）来凑。
- 现场演示用真实 App，嵌入在网页里的手机框中（iframe），不切换窗口。
- 部署到服务器，不依赖 localhost。
- 画像演化、目标改道当作**已实现功能**来讲（由其他人并行实现）。
- 路演时长不限，可以充分发挥。

### 6.1 画像演化（场景 11）的分拍

1. **起点**：画面左侧是林夏的季初画像（第 0 张快照），右侧一片黑暗。
2. **命运树生长**：13 层分叉从左往右展开（第 1–13 周），每个节点有 2–3 条出路，对应 `direction`：超额 / 照做 / 偏离 / 转向。没走过的分支是暗线。
3. **真实路径**：一道光沿林夏真实走过的路径流动；镜头在 3–4 个关键节点停下，弹出那一周的真实记录原话和 `PortraitShift.headline`，节点旁的画像缩略图随之变化（读 E7 的快照数据）。
4. **路径末端**：林夏的真实终点画像亮起。
5. **拉远**：镜头不断后退，树的所有末端开出画像，越来越多，最后铺满整面墙，大约 60–120 个「平行的她」（用 8–16 张分支画像做变体）。字幕：「每一个节点，她都可能成为另一个人。」
6. **收拢**：画像一张张熄灭，只留下真实的那一张，回到画面中央，旁边打出：「这是她自己选出来的。」
7. **对照**：季初画像和季末画像并排，中间写着「拟合 13 次」，接到场景 12。

视觉原则：偏离或转向的分支画像**气质不同，但同样好看**（不变暗、不变丑、不用灰度来表示「差」）。暗只代表「没有走这条路」，不代表「这条路更差」。

## 7. 交互与演讲控制

- 下一步：`→` `↓` `空格` `PageDown` `Enter`（兼容常见翻页笔）；上一步：`←` `↑` `PageUp`。
- `F` 切换全屏，`B` 黑屏，`Home` / `End` 跳到首 / 尾，数字键加 `Enter` 跳转到指定场景。
- 当前位置写进 URL hash（`#11.3` 表示场景 11 第 3 拍），刷新不会丢位置。
- **iframe 焦点问题**：点击 iframe 之后，键盘事件会进入 iframe。处理方式：iframe 和父页面同源，父页面同时监听 `iframe.contentWindow` 上的 keydown，只转发翻页类按键（我的决定）。如果 App 里正好有输入框（比如采访作答），就不转发，避免打字时误翻页。
- 鼠标：屏幕底部有一条细进度条，悬停时显示场景缩略目录，点击可以跳转（演讲者自用）。
- **演讲者备注（P1）**：按 `S` 弹出第二个窗口 `/pitch/notes`，通过 `BroadcastChannel` 同步当前场景，显示台词要点和下一屏预告。

## 8. 数据

- 场景 8、9、11 读 `seed/demo-season.json`（已存在，林夏 13 章）和 `seed/pitch-branches.json`（待办 E8，还不存在）。快照数据（待办 E7）还不存在。
- **读取方式**：`app/pitch/page.tsx` 是服务端组件，在服务端读取 seed JSON，**只裁出用到的字段**（标题、封面、类型、少量记录原话、快照）作为 props 传给客户端组件。`demo-season.json` 有 165KB，不整份打进客户端。ESLint 没有禁止前端导入 `seed/`，但这个读取只放在服务端组件里。
- 在 E7 / E8 就绪之前，用 `components/pitch/placeholderData.ts` 提供**同结构**的占位数据：画像先用 `sheet-future.jpg` 做变体。数据就绪后，切换成读真实文件，改动只在 page.tsx 的一处。
- 字段结构以待办文档 §0.1、§0.2、E7、E8 为准。路演页在 `components/pitch/types.ts` 定义 `PitchData`，作为数据形状的唯一来源；占位数据和真实数据都必须先转换成它（我的决定）。
- **快照放在哪里**（我的决定，已同步到待办 E7）：`seed/demo-season.json` 顶层新增 `portraitSnapshots[]`，覆盖 chapterNo 0–13，每项 `{ chapterNo, imageUrl, profile, shift }`，与 §0.1、§0.2 一致。
- **真实路径的 `direction`**：优先用快照里的 `shift.direction`；在快照就绪之前，从 `chapterType` 映射（highlight→ahead，struggle→on_track，low/rest→drift）。
- **命运树由数据驱动**（我的决定）：`pitch-branches.json` 中每项的 `path` 是长度为 13 的 direction 数组，树的分叉就由这些路径的前缀合并而成。真实路径来自快照。为了画面密度，另外生成一些纯装饰的暗分支（没有画像），装饰分支只在拉远阶段出现。

## 9. 布局绕开

- `MobileShell`、`AppChrome` 用 `usePathname()` 判断，`/pitch` 开头的路径直接返回 `children`，不渲染外框、`TabBar`、`DemoPanel`。
- **嵌入模式**（我的决定）：iframe 加载 `/season?embed=1`。`AppChrome` 读到 `embed=1` 后写入 `sessionStorage`，之后在 iframe 内的页面跳转中持续隐藏 `DemoPanel`，避免评委看到开发者按钮。`TabBar` 照常显示。
- `PaperBackground` 在 `/pitch` 下被舞台的不透明背景盖住即可，不改它。
- 视口 `themeColor` 不受影响。

## 10. 现场演示（场景 10）

- iframe 的 `src` 是相对路径 `/season`（同源，部署到哪个域名都适用）。尺寸是 430×932 逻辑像素，小于 760，所以 App 会去掉自己的外框；路演页自己画一个手机外框，放大约 1.0–1.1 倍。
- 进入场景 10 时才挂载 iframe（我的决定：避免路演开始就触发请求），离开后保留挂载，返回时状态还在。
- 场景 10 的第 0 拍有一个演讲者专用的小按钮「重置演示」，依次调用已有的 `api.demo.seed()` 和 `api.demo.fastForward({ chapter: DEMO_START_CHAPTER })`。起始章节是一个常量，默认是 4。这个按钮要放在评委看不到的地方，或者只在悬停时显示。
- **演示起点暂不锁定**（用户决定：演示数据还在整理）。路演页不依赖起点状态。等演示数据定稿后，再决定是否请 B 轨道在 `lib/server/demo.ts` 加「预勾到只剩 N 个任务」的能力；字幕的拍子到时候再按最终流程调整。
- **生成默认走缓存回放**（用户决定）：演示中触发的章节生成走 `cached=1` 路径（前端模拟流式）。部署环境必须开启 `DEMO_MODE`。
- **降级**：
  1. App 已有的缓存模式（`/api/demo/fast-forward?cached=1`）
  2. 场景 10 内按 `V` 切换到备用视频 `public/pitch/backup-demo.mp4`（视频由 D 轨道录制；没有视频文件时显示提示，不报错）

## 11. 视觉方向

- 我的决定：沿用 App 的「纸 / 墨 / 金」配色和 Noto Serif SC 字体，保证产品和路演是同一种气质；但研究推理链和画像演化这两段用**深色舞台**（墨色底 + 金色光），开场的黑场、命运树的光才显得出来。场景 8–10 回到纸色，因为这是在「进入她的故事」。
- 大屏字号：主张一句话 ≥ 72px，正文 ≥ 32px，注脚 ≥ 20px（以 1920 画布计）。
- 每屏最多一个主张；数据配一个可视化（大数字、对比条），不用表格，除了场景 12 的矩阵。
- 动画用 framer-motion。尊重 `prefers-reduced-motion` 不是必须的（演讲者自己的设备），但所有动画都必须能被「下一步」打断并直接跳到终态。

## 12. 验收

- `pnpm check` 通过。
- 在 1920×1080、1366×768、2560×1440 三种视口下，构图一致、没有溢出。
- 只用键盘就能从场景 0 走到场景 17，可以回退，刷新后停在原来的位置。
- 场景 10：在部署后的域名下（已开启 `DEMO_MODE`），点「重置演示」后，iframe 里能完整走完「勾任务 → 迷雾散开 → 缓存回放生成章节」；点进 iframe 之后翻页键仍然有效；在输入框里打字不会误翻页。
- 断网时，除场景 10 以外的所有场景都能正常显示。
- 场景 11 全程流畅（目标 60fps，满墙阶段不低于 30fps），在中等配置的笔记本上测。
- 占位数据换成真实 seed 数据时，只改 `page.tsx` 一处。
